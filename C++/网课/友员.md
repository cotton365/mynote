友元函数前面加 `friend` 说明，这类东西被赋予了更高的权限。  
对于函数而言，这个函数可以访问到类里面的私有成员，或者说保护成员。  
对于友元类而言，需要在对应的被访问的类里面显式声明。确实，被访问的类，它显式声明的效果就是可以被友元类访问私有成员。




### 1. 友元类的“绝对权力”（它能做什么）

假设有一个 `House`（房子）类，里面藏着最私密的 `safePassword`（保险柜密码）。现在我们把 `Thief`（小偷）类声明为友元：
```cpp

class House {
private:
    int safePassword;          // 私有密码
    void privateAlarm() {}     // 私有报警系统
public:
    House(int p) : safePassword(p) {}
    // 【关键声明】小偷类是我家的友元
    friend class Thief;
};
class Thief {
public:
    // 小偷的成员函数
    void steal(const House& h) {
        // 直接读取私有密码！编译通过！
        int pwd = h.safePassword;
        
        // 直接调用私有报警函数！编译通过！
        // 虽然调用报警很蠢，但语法上完全允许
        h.privateAlarm();
    }
};
```
在这个例子里，`Thief` 类的**所有成员函数**（`steal`、`pickLock` 等）都获得了同等的最高权限，可以直接触碰 `House` 里的任何东西。

### 2. 友元类永远绕不开的“三大铁律”（边界）

虽然友元类权限极大，但它终究是“外人”，永远被这三条规则死死框住：

#### 铁律一：**友元关系是“单向”的（你主动，我不主动）**

- `House` 声明 `Thief` 是友元，意味着 `Thief` 可以翻 `House` 的家。
    
- 但是，**`House` 反过来绝对无法访问 `Thief` 的私有成员**！除非 `Thief` 也大方地声明 `House` 是它的友元。
    
- **大白话**：你把你家钥匙给了小偷，不代表小偷会把他家的钥匙给你。
    

#### 铁律二：**友元关系“不继承”（父子分家）**

假如有个 `MasterThief`（神偷）类继承了 `Thief` 类：

```cpp

class MasterThief : public Thief {
public:
    void hack(const House& h) {
        // 报错！无法访问 House 的私有成员！
        // int p = h.safePassword; 
    }
};
```

**原因**：`House` 只信任 `Thief` 这个特定类，它不认识 `Thief` 的儿子。权限是实名制的，不能代代相传。

#### 铁律三：**友元关系“不传递”（朋友的朋友，我不认识）**

如果 `Thief` 又声明了 `Accomplice`（同伙）是它的友元：

```cpp

class Accomplice {
public:
    void help(const House& h) {
        // 报错！无法访问 House 的私有成员！
        // 虽然我是 Thief 的朋友，但 House 不认识我。
    }
};
```
**原因**：`House` 只认在自己类里明确写过的 `friend class Thief`。除非你在 `House` 里再加一行 `friend class Accomplice`，否则免谈。
